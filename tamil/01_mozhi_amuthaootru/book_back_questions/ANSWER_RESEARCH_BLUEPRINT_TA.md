## 1. பணியின் நோக்கம்

இந்தக் கட்டத்தின் வேலை **மாணவர் விடைகளை எழுதுவது அல்ல**. ஒவ்வொரு கேள்விக்கும் பிற கல்வி இணையதளங்கள் அல்லது Guide PDF-களில் அந்த விடை எங்கு உள்ளது என்பதைத் தேடி, அந்தப் பக்கத்தின் நேரடி இணைப்பைத் தருவதே முதன்மை.

- கேள்வி உரை, வரிசை, எண், பிரிவு ஆகியவை `questions.md`-இல் உள்ளபடியே இருக்க வேண்டும்.
- Non-objective கேள்விகளுக்கான விடையை ChatGPT உருவாக்கக்கூடாது; paraphrase செய்யக்கூடாது; பல source-களை ஒன்றிணைத்து எழுதக்கூடாது.
- அந்தக் கேள்விக்குப் பதில் உள்ள எல்லா சரிபார்க்கக்கூடிய source-களையும் சேர்க்க வேண்டும். மூன்று அல்லது ஐந்து source என்று எண்ணிக்கை வரம்பு இல்லை.
- source பக்கத்தில் விடை இருப்பதை நேரடியாகத் திறந்து பார்த்த பிறகே `ANSWER_FOUND` எனக் குறிக்க வேண்டும்.
- Search snippet, homepage, index page மட்டும் விடை இருப்பதற்கான சான்றல்ல.
- கிடைக்காத இடங்களில் ஊகிக்காமல் `ANSWER_NOT_FOUND`, `QUESTION_MISMATCH`, `ACCESS_BLOCKED` போன்ற துல்லியமான நிலையைச் சேர்க்க வேண்டும்.

## 2. GitHub-ன் பங்கு

GitHub பல AI/கருவிகள் ஒரே temporary working file-ஐப் பகிர்ந்து கொள்ளும் இடம் மட்டுமே. இது மாணவர் பயன்பாட்டுக்கான இறுதி Website அல்ல.

- Deploy / publish / merge to `main` / site routing மாற்றம் செய்யக்கூடாது.
- User-ன் ஒப்புதல் இல்லாமல் பழைய branch அல்லது கோப்புகளை delete செய்யக்கூடாது.
- User தேவையான data-ஐ எடுத்துக்கொண்ட பிறகு temporary content cleanup-ஐ அவரே செய்வார்.
- `questions.md`, quiz கோப்புகள், textbook PDF, page mapping, website code ஆகியவை இந்த Answer Source Collection பணியில் மாற்றப்படக்கூடாது.

## 3. Answer கோப்பின் துல்லியமான வடிவம்

### 3.1 ஒரு மதிப்பெண் / ஒருசொல் / MCQ

இந்த வகைக்கு மட்டும் source-ல் உண்மையாகக் காணப்பட்ட:

1. **சரியான விடை / தெரிவு:** விருப்பக் குறியீடு + குறுகிய விடை உரை.
2. **💡 காரண விளக்கம்:** ஒரு மதிப்பெண் / one-word வினா என்றால், அது இலக்கண வினாவாக இருந்தாலும் சரி, சொற்பொருள் / பாடப்பொருள் / இலக்கியம் / பொது அறிவு / வகைப்பாடு சார்ந்ததாக இருந்தாலும் சரி, அந்த விடை ஏன் சரி என்பதை மாணவர் புரிந்துகொள்ள உதவும் சுருக்கமான விளக்கத்தைத் தர வேண்டும். இலக்கணம் அல்ல என்று மட்டும் காரண விளக்கத்தைத் தவிர்க்கக்கூடாது.
3. **விளக்கத்தின் ஆதார முன்னுரிமை:**
   - முதலில் அதே பாடநூலின் தொடர்புடைய வரி, சொற்பொருள், அட்டவணை, பாடப்பகுதி அல்லது விதியைத் தேடு.
   - அடுத்து அதே கேள்வி/விடையை விளக்கும் நம்பகமான கல்வி source அல்லது Guide-ஐத் திற.
   - இலக்கணக் கேள்வி என்றால் பொருந்தும் இலக்கண விதி source-ஐக் குறிப்பிடு.
   - பொதுப் பொருள் / பாடப்பொருள் வினா என்றால் பாடநூல் தகவல் அல்லது தொடர்புடைய நேரடி source-ஐக் கொண்டு காரணம் எழுது.
4. **Extractor-written explanation:** விளக்கம் source-ல் அப்படியே இருந்தால் source-ன் விளக்கம் என்று குறிப்பிடு. பல ஆதாரங்களில் உள்ள தகவலைப் படித்து extractor சுருக்கமாக எழுதினால் `Extractor-written explanation based on cited source` என்று label செய்து, அதற்கான direct URL-ஐ இணை. ஆதாரமில்லாத சொந்த ஊகம் கூடாது.
5. **விளக்கத்தின் நீளம்:** பொதுவாக 1–3 எளிய வரிகள்; தேவையான இடத்தில் ஒரு முக்கிய சொல்/விதி மட்டும்.
6. **Source records:** ஒவ்வொரு Answer Website-ம் தனித்தனியாக; ஒவ்வொன்றில் அந்தத் தளம் காட்டும் option/answer மட்டும்.
7. **Conflict:** வெவ்வேறு தளங்கள் வெவ்வேறு விடை சொன்னால் இரண்டையும் அப்படியே பதிவு செய்து `CONFLICT` எனக் குறிக்க வேண்டும்.
8. **ஆதாரம் கிடைக்காத நிலை:** விடை மட்டும் source-ல் உள்ளது; காரணத்தை ஆதரிக்கும் பாடநூல்/விதி/விளக்க source கிடைக்கவில்லை என்றால் காரணத்தை உருவாக்காமல் `EXPLANATION_SOURCE_NOT_FOUND` என்று பதிவு செய். விடை ஆதாரத்தையும் விளக்க ஆதாரத்தையும் தனித்தனியாகக் காட்டு.

### 3.2 குறுவினா / சிறுவினா / நெடுவினா / திறந்தநிலைப் பயிற்சி

இந்தக் கேள்விகளுக்கு **விடை எழுதவே கூடாது**. கேள்விக்குப் பிறகு கீழ்க்கண்ட மூன்று heading-களும் காலியாக இருக்க வேண்டும்:

- 🔑 **விடைக்குறிப்பு:** `[TO_BE_PREPARED_LATER]`
- 📝 **சாதாரண விடை:** `[TO_BE_PREPARED_LATER]`
- 📖 **விரிவான விடை:** `[TO_BE_PREPARED_LATER]`

அதற்குப் பிறகு அந்தக் கேள்விக்குப் பதில் உள்ள source-களின் பெயர், நேரடி Page/PDF Link, Title/Date/Edition (தெரிந்தால்), page number (PDF என்றால்), exact question match நிலை ஆகியவற்றை மட்டும் தர வேண்டும். Source-ன் நீண்ட பதிலை இங்கே நகலெடுக்கவோ சுருக்கி சொந்த பதிலாக மாற்றவோ கூடாது.

## 4. Source பதிவு வடிவம்

ஒவ்வொரு source-க்கும் தனி record:

- **Source:** தளம் / வெளியீட்டாளர் / Guide பெயர்.
- **Direct page/PDF:** குறிப்பிட்ட விடை உள்ள நேரடி இணைப்பு.
- **Title / date / edition:** பக்கத்தில் இருந்தால்.
- **Location:** HTML section அல்லது PDF page number.
- **Question match:** `EXACT_MATCH`, `WORDING_VARIANT`, `QUESTION_MISMATCH`.
- **Answer status:** `ANSWER_FOUND`, `PARTIAL_SOURCE`, `ANSWER_NOT_FOUND`, `ACCESS_BLOCKED`, `GUIDE_PRODUCT_PAGE_ONLY`.
- **Objective answer only:** அந்த source காட்டும் சரியான குறுகிய option/answer text.
- **Reason source:** காரண விளக்கத்துக்கான இலக்கண விதி ஆதாரம் தனியாகக் குறிக்கப்பட வேண்டும்.

ஒரே source-ன் இரண்டு பதிப்புகள் இருந்தால் அவற்றை ஒன்றாகக் கருதக்கூடாது. Source 1/Source 2 விடைகளை merge செய்யக்கூடாது.

## 5. காரண விளக்கம் — எல்லா one-mark வினாக்களுக்கும் பொருத்தமான ஆதார விளக்கம்

காரண விளக்கம் இலக்கண வினாக்களுக்கு மட்டும் அல்ல. ஒவ்வொரு one-mark / one-word வினாவிலும் சரியான விடை ஏன் சரி என்பதை விளக்க முடியுமா என்று பார்க்க வேண்டும்.

### 5.1 விளக்க வகையைத் தேர்வு செய்
- **இலக்கண விளக்கம்:** புணர்ச்சி, சொல்வகை, தொழிற்பெயர், வினையாலணையும் பெயர் போன்ற இலக்கண விதி / இலக்கண வகை.
- **பாடநூல் விளக்கம்:** பாடநூலில் கொடுக்கப்பட்ட வரையறை, சொற்பொருள், எடுத்துக்காட்டு, அட்டவணை, பாடல்/உரைப் பொருள்.
- **பொது / கருத்து விளக்கம்:** கேள்வி சார்ந்த தகவல் அல்லது வகைப்பாட்டை நேரடியாக விளக்கும் ஆதாரம்.
- **விளக்கம் தேவையில்லை என்று முடிவு செய்யும் முன்:** அந்த one-mark வினாவுக்கு பாடநூல் அல்லது நம்பகமான source-ல் விளக்கத் தகவல் உள்ளதா என்று தேடு. இலக்கணம் அல்ல என்பதற்காக மட்டும் `REASON_NOT_REQUIRED` என்று எழுதக்கூடாது.

### 5.2 ஆதாரம் மற்றும் எழுதும் முறை
1. முதலில் பாடநூலின் தொடர்புடைய பாடப்பகுதி / சொல்லும் பொருளும் / அட்டவணை / விதியைப் பார்க்கவும்.
2. பிறகு அதே கேள்வி அல்லது சரியான விடையை விளக்கும் நேரடி source page-ஐத் திறக்கவும்.
3. அந்த ஆதாரம் விடை ஏன் சரி என்பதை உண்மையில் விளக்குகிறதா என்று சரிபார்.
4. ஆதாரத்தை அடிப்படையாகக் கொண்டு 1–3 வரிகளில் எளிய தமிழில் விளக்கத்தை எழுதலாம்.
5. Source-ல் உள்ள விளக்கத்தை நேரடியாகச் சுருக்கமாகக் கூறினால் source-ஐக் குறிக்கவும். Extractor தன் சொற்களில் தொகுத்தால் `Extractor-written explanation based on cited source` என்று தெளிவாக label செய்யவும்.
6. காரணம் எழுதுவதற்கான ஆதாரம் இல்லையெனில் ஊகிக்க வேண்டாம்; `EXPLANATION_SOURCE_NOT_FOUND` என்று பதிவு செய்.
7. ஒவ்வொரு காரண விளக்கத்திற்கும் அதன் direct source URL அவசியம். விடைக்கான source மற்றும் காரண விளக்கத்திற்கான source வேறுபட்டிருக்கலாம்; இரண்டையும் தனித்தனியாகக் காட்டு.

## 6. Guide PDF தேடல் விதி

- Sura, Don போன்ற வெளியீட்டாளர்களின் Guide title, edition, class, subject ஆகியவற்றைத் தேடு.
- Product/retailer page மட்டுமே கிடைத்தால் `GUIDE_PRODUCT_PAGE_ONLY` எனக் குறி. அது PDF அல்லது Answer page என்று கூறக்கூடாது.
- PDF திறக்கப்பட்டு சரியான கேள்வி அதில் உள்ளதா, விடை எந்த PDF page-ல் உள்ளதா என்று பார்த்த பிறகே `ANSWER_FOUND` எனக் குறி.
- PDF page number தெரியாவிட்டால் ஊகிக்க வேண்டாம்; `PDF_PAGE_NOT_VERIFIED` என்று குறிப்பிடு.
- Free PDF கிடைக்கவில்லை என்றால் அதை வெளிப்படையாகச் சொல்; கிடைக்காத PDF link உருவாக்கக்கூடாது.

## 7. பதிப்புரிமை மற்றும் source fidelity

- ஒரு option அல்லது ஒரு சொல் போன்ற குறுகிய objective answer-ஐத் துல்லியமாகக் குறிக்கலாம்.
- நீண்ட Guide/Website விடைகளை முழுவதுமாக word-by-word நகலெடுக்காமல், நேரடி இணைப்பு மற்றும் தேவையான இட விவரத்தை மட்டும் கொடு.
- Source-ல் உள்ள சொற்களை அப்படியே தராவிட்டால் அதை verbatim என்று கூறக்கூடாது.
- Non-objective answers-க்கு இந்தக் கோப்பில் source link மட்டுமே போதும்; user பின்னர் source-ஐத் திறந்து ஒப்பீடு செய்து தன் சொந்த பதிலை உருவாக்குவார்.

## 8. QC குறிச்சொற்கள்

| Status | பொருள் |
|---|---|
| `EXACT_MATCH` | Source கேள்வி wording `questions.md`-உடன் பொருந்துகிறது |
| `WORDING_VARIANT` | அதே கேள்வி; சிறிய சொல்/எழுத்து வேறுபாடு உள்ளது |
| `QUESTION_MISMATCH` | வேறு கேள்வி அல்லது பொருள் மாறும் அளவிலான வேறுபாடு |
| `CONFLICT` | இரண்டு அல்லது அதற்கு மேற்பட்ட source-கள் மாறுபட்ட பதில் தருகின்றன |
| `ACCESS_BLOCKED` | தற்போதைய முயற்சியில் நேரடியாகத் திறக்க முடியவில்லை |
| `ANSWER_NOT_FOUND` | திறந்த source-ல் குறிப்பிட்ட கேள்விக்கான பதில் இல்லை |
| `PARTIAL_SOURCE` | பகுதி விடை மட்டுமே உள்ளது |
| `GRAMMAR_RULE_NOT_FOUND` | பொருந்தும் இலக்கண விதி ஆதாரம் உறுதி செய்யப்படவில்லை |
| `GUIDE_PRODUCT_PAGE_ONLY` | Guide விற்பனைப் பக்கம் மட்டும்; PDF/விடை சரிபார்க்கப்படவில்லை |

## 9. ஒவ்வொரு கேள்விக்கும் முடிவு

- Objective: Source-ல் உள்ள விடைகள் தனித்தனியாக + எல்லா one-mark வகைகளுக்கும் பொருத்தமான source-based காரண விளக்கம் + விளக்க source links.
- Non-objective: மூன்று placeholder-கள் காலியாக + விடை உள்ள எல்லா direct page/PDF links.
- எந்தக் கேள்விக்கும் சொந்தமாக உருவாக்கிய மாணவர் விடை கிடையாது.
- முக்கியமான mismatch/conflict/access issue இருந்தால் மட்டும் குறுகிய QC Note.
- `questions.md` அசல் உள்ளடக்கம் மாற்றமில்லாமல் இருக்க வேண்டும்.

## 10. ஒரு வரி நினைவூட்டல்

**Non-objective = மூன்று காலி placeholder + எல்லா சரிபார்க்கப்பட்ட source links மட்டும்; Objective = source-ல் உள்ள குறுகிய விடை + இலக்கணம்/பாடநூல்/பொது விளக்கம் எனப் பொருத்தமான source-based காரண விளக்கம்; சொந்த model answer எதுவும் இல்லை.**


## 11. Answer-to-Quiz handoff — quiz.start

- `answers.md`-ல் verify செய்யப்பட்ட one-mark / one-word வினா, source-wise correct answer, காரண விளக்கம், விளக்க source URL ஆகியவை முதன்மை data.
- இந்தத் தகவல்களே பின்னர் `quiz.start.md` மற்றும் `quiz.start.json`-க்கு எடுத்துச் செல்லப்பட வேண்டும்; இரண்டு இடங்களிலும் answer / explanation முரண்படக்கூடாது.
- பாடநூலில் ஏற்கெனவே நான்கு options உள்ள MCQ-களில் அசல் கேள்வி மற்றும் options பாதுகாக்கப்பட வேண்டும்; உறுதி செய்யப்பட்ட correct option index / answer text மட்டும் இணைக்க வேண்டும்.
- பாடநூலில் one-mark ஆக உள்ள fill-in-the-blank, பொருத்துக, கூற்று அல்லது வேறு objective வடிவங்களை நான்கு options கொண்ட MCQ-ஆக மாற்றலாம்: ஒரு சரியான விடை + மூன்று பொருத்தமான தவறான options.
- பெரிய/நீண்ட விடை வினாக்களிலிருந்து புதிய one-word / MCQ வினாக்களை உருவாக்கக்கூடாது. Book-back-ல் உள்ள objective/one-mark வினாக்களே quiz scope.
- Answer source conflict தீர்க்கப்படாத வினா final quiz-க்கு செல்லக்கூடாது; `CONFLICT_REVIEW_REQUIRED` என நிறுத்தப்பட வேண்டும்.
- இந்த branch-ல் `quiz.start.md`, `quiz.start.json` அல்லது அவற்றின் canonical schema இல்லை. Antigravity-யிடம் இருந்து field schema, ID rule, sample files கிடைக்கும் வரை அவற்றை உருவாக்க வேண்டாம்.
- தற்போதைய `quiz.md` / `quiz.json` ஏற்கெனவே உள்ள artifact-கள்; அவற்றை quiz.start schema என்று கருதவோ இந்தப் பணியில் overwrite செய்யவோ கூடாது.
